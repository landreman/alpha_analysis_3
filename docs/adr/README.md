# Architecture and scientific decisions

DESIGN.md records the approved baseline. Write a short numbered ADR
(`NNNN-short-title.md`) for a new unresolved physics or acceptance ambiguity, a proposed
dependency or core-boundary change, or a measured feasibility obstruction. Routine
implementation choices need no approval loop.

Structure: title; status (proposed / accepted / rejected / superseded); date; affected
milestone; evidence and problem; options and consequences; proposed decision; tests or
benchmarks needed. A proposed ADR does not authorize its own decision: put it in a draft PR,
stop the affected implementation, and let the researcher decide.

The ADRs of the earlier repositories are historical evidence, not decisions to copy. The
decisions in DESIGN section 1 are already accepted.
